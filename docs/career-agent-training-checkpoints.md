# 训练步骤恢复与模型基线

训练任务的进度卡显示「待查题」「题目已保存」「计划草稿已保存」「计划已保存」。Flyway V7 在原任务表中增加题目目录和计划草稿两处检查点及写入时间。旧任务继续读取原有状态和结果，未完成的旧任务从第一个可用检查点开始。Java 和 Python 的内部工具契约一并更新。

| 检查点 | 保存内容 | 重新领取后的动作 |
| --- | --- | --- |
| 查题完成 | 当前岗位方向的公开题干、选项、来源和版本 | Python 复用目录，直接调用生成计划工具 |
| 生成完成 | Java 验证后的岗位分析、步骤和所选题目快照 | Java 直接保存计划结果，省去模型调用 |
| 保存完成 | 最终结果和 `SUCCEEDED` 状态在同一更新中写入 | 相同请求编号与内容返回已有结果 |

Python 检查工具名称、调用数量和参数结构。计划生成收到无效工具响应时，复用已保存的题目目录补试一次。若补试仍失败，任务卡会提示模型返回格式错误，并保留查题进度。Java 按内部服务令牌和当前任务租约授权，校验计划引用属于已保存目录，并拒绝重复题目和不同内容的草稿覆写。阶段记录与任务 ID 对应，模型日志记录任务 ID、步骤、调用耗时及供应商返回的输入和输出 token。

## 真实模型基线

按[本地启动说明](career-agent-day-1-2026-11-06.md)启动服务。准备一个没有已确认经历和练习记录的演示账号，在模型配置中保存支持工具调用的默认对话模型。下列命令从 `api` 目录运行，会为演示账号写入合成岗位和经历，并生成一组训练、复习与面试任务。

```powershell
uv run --locked python -m scripts.check_career_workflow demo_user
```

脚本输出每个任务的 ID、最终状态与端到端耗时。按任务 ID 从 Python 日志找到对应的 `Career model` 行，汇总输入和输出 token。供应商未返回的 usage 记为缺失。重新测量时使用新的演示账号和同一模型，以避免历史练习影响复习输入。

2026-11-09 通过 Vite、Java、隔离 MySQL、Python 和现有 Comet 模型配置，使用 `deepseek-flash` 跑通一组固定合成岗位与经历。三项各运行一次。耗时包含派发、保存和脚本轮询，token 来自供应商返回的 usage。

| 任务 | 状态 | 端到端耗时 | 输入 token | 输出 token |
| --- | --- | ---: | ---: | ---: |
| 训练计划 | 成功 | 11.336 秒 | 1,412 | 609 |
| 复习建议 | 成功 | 8.305 秒 | 1,424 | 884 |
| 模拟面试 | 成功 | 7.170 秒 | 570 | 668 |

训练计划耗时覆盖查题和生成两次模型调用。以上是功能验收和单样例基线，后续对照实验沿用相同模型与输入设置。

### 用练习反馈改进备考计划

备考 Harness 在提交新计划时，读取当前用户、当前岗位近 30 天最多 60 次客观题作答。每道题以最后一次结果作为证据。同一必备技能下至少两道不同题的最后一次作答错误，且错误比例达到一半时，才生成复习优先项。保存策略版本与证据作答编号到任务快照，模型只收到必要的技能和推荐题目引用。

候选排序先满足指定题和岗位技能覆盖，再优先保留该薄弱技能的未做客观题。模型仍只能选择已冻结目录内的 ID 和版本。计划详情展示薄弱点、样本数以及本计划是否采用推荐，下一轮重新从作答记录计算。既有计划沿用提交时的证据和候选检查点。策略由后端代码控制，学习范围为岗位内备考选题，设计参考 [Reflexion](https://proceedings.neurips.cc/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html) 的跨轮使用执行反馈，以及 [OpenAI Harness Engineering](https://openai.com/index/harness-engineering/) 的可验证反馈循环。

在 `api/` 运行 `python -m eval.career_training_harness_eval` 可复跑对照。8 个合成案例中，备考反馈策略使用同一题库与岗位要求，让薄弱技能下的未做题进入前 4 的案例从 2 个增加至 8 个，必备技能覆盖保持 25/25，指定题保留保持 8/8。评测范围为模型前的候选排序，真实模型采纳率与用户后续答对率需单独测量。

### 训练计划选题匹配

已接入 Python 候选目录和模型入口。岗位技能按别名归并并优先纳入覆盖未满足技能的代表题，模型预算内优先保留指定题。模型仍只能从已持久化目录中引用精确题目版本。技能覆盖率对照待使用人工标注数据测量。

- Java 筛选候选题时，先用技能词表归并主题与别名，再按岗位必备技能分组保留代表题，剩余名额按相关性补齐。用户指定题优先保留，并在 Python 应用 token 预算时确保它进入模型可见目录。
- 沿用 `create_training_plan` 调用，在提示词中要求优先覆盖岗位必备技能，再结合已有面试反馈选择用户的薄弱项。候选目录缺少对应题时，在岗位分析中说明覆盖缺口。
- 用同一批人工标注必备技能的岗位描述和固定题库，对比送入模型的候选目录与最终计划各自的必备技能覆盖率。补充检查指定题保留和题库缺项两个场景。

### RAG 父块去重与候选补足（2026-11-19）

已接入普通混合检索和向量阈值检索。按用户批量查询父块，并校验文档、知识库范围。保留最高排名子块的评分和来源，父块缺失或范围不符时使用子块。重复父块之后的位置由候选继续补足。

- 当前情况。`api/app/core/rag/search.py` 在子块排序后逐条回查父块，未显式按 `parent_id` 去重。多个子块命中同一父块时，会重复查询并返回相同父块内容，重复结果占用上下文 Token 和 `top_k` 名额。`api/app/core/agent/tools/builtin/knowledge.py` 的引用去重仍会逐条拼接正文。
- 优化方案。保留子块相关性排序，按父块标识合并同一父块的命中，保留排名最高的子块作为代表，并向后扫描候选以补足最多 `top_k` 个不同父块。无父块的结果按自身块标识处理，父块缺失时保留子块内容回退。扩大或保留重排序输出候选，候选不足时返回实际可用数量。
- 查询与契约。对唯一父块批量回查或使用请求内缓存，继续校验用户隔离。保留代表子块标识、来源和评分语义。普通混合检索与 `min_vector_score` 分支均需覆盖。
- 验收要求。多个子块属于同一父块时仅返回一次正文，候选充足时能补足 `top_k` 个不同父块。验证不同父块、无父块、父块缺失、重排序启用或失败、向量阈值分支及跨用户隔离，并对比父块查询次数、上下文 Token 和结果覆盖范围。

### 岗位对话上下文管理（2026-11-20）

新岗位消息将可识别约束随原消息保存，历史消息继续解析原文。装配时按用户、会话和岗位选择每个字段最新的明确陈述，保留 `message_id` 并覆盖最近窗口之外的历史。文本模型首次调用按 `CAREER_CHAT_CONTEXT_WINDOW` 和输出预留，扣除系统提示、工具描述和协议开销后分配正文与完整历史轮次。运行期工具结果和多模态输入的统一预算仍待实现。

- 当前情况。岗位聊天按用户、会话和岗位读取最多 80 条消息，保留最近 8 条，其余按规则摘录并保留 `message_id`。每条旧消息最多摘取一句，同一条消息中的多项约束可能遗漏。用户明确更正后，旧值和新值可能一起进入模型输入。
- 第一步。按句或短段提取约束，允许一条消息保留多项约束。复习顺序、截止时间等可明确识别的字段遇到用户更正时，标记旧值已被替代，装配时优先放入当前有效值，并保留来源 `message_id`。会话内约束遵循用户、会话和岗位范围，已保存的岗位偏好及简历版本由 Java 提供。
- 第二步。按完整交互装配最近历史，用模型窗口扣除系统提示、工具定义和预留输出后分配输入预算，计入附件及工具结果开销。将有效约束随会话持久化，覆盖来源早于最近 80 条消息的场景。长附件和工具结果保留引用，按用户和岗位权限回查原文。达到预算阈值时再评估是否引入模型摘要。
- 验收要求。扩展 `api/eval/career_history_eval.py` 及标注集，覆盖一条消息含多项约束、显式更正及超过 80 条消息的对话。比较有效约束召回率、已替代约束进入模型输入的比例、平均历史 Token，并验证来源可回查。现有离线基线为 72 条合成对话保留 142/144 条标注约束（98.61%），平均历史输入 1,845.36 Token。

### Redis 跨实例缓存（候选优化，待评估，2026-11-23）

实现了两个默认关闭的试验开关。当前通过测试替身验证用户隔离、MCP 并发重建、配置版本切换和 Redis 不可用时的回退。真实 Redis 与模型调用的延迟和命中率待实测。

- `MCP_SHARED_TOOL_CACHE_ENABLED` 仅共享声明式工具描述与 Schema，使用用户、服务与配置版本隔离。调用工具时按当前授权配置建立连接。目录锁和过期时间限制多实例重复加载。
- `MEMORY_SHARED_RECALL_CACHE_ENABLED` 共享短期加密的查询向量，按用户、模型和查询隔离。当前轮仍向 Neo4j 查询最新事实，因此删除与修订不依赖 Redis 清除旧正文。该开关避免复用上一轮查询的召回正文。

- **MCP 工具列表缓存。** 目前按用户在进程内缓存工具对象，TTL 为 300 秒，已启用的服务配置指纹变化时重新加载。评估将工具名、描述和参数 Schema 等可序列化元数据放入 Redis，运行时按当前配置构建可执行工具。设计跨实例失效机制，覆盖服务增删改、启停和手动同步，并验证缓存失效后并发请求只触发一次重建。参见 [MCP 工具加载](../api/app/core/agent/tools/mcp/loader.py)。
- **长期记忆召回缓存。** 目前普通对话通过进程内字典复用同一用户上次的召回结果，并在后台刷新。评估通过 Redis 跨实例复用时，按用户隔离并设置 TTL，区分用户通用画像和依赖当前问题的召回结果。记忆更新、删除后应跨实例失效，并防止较早发起的后台刷新写回已失效内容。优先评估缓存最小必要数据，如记忆 ID 或筛选后的摘要，并明确敏感信息的缓存范围。参见 [召回与后台刷新](../api/app/services/chat_service.py#L260)。
- **验收。** 用同一批请求对比进程内缓存和 Redis 共享缓存，记录跨实例命中率、MCP 清单拉取或记忆召回次数、首字延迟。验证配置或记忆变更后的失效传播、并发重建、用户隔离和 Redis 不可用时的回退。根据实测收益决定是否迁移。
