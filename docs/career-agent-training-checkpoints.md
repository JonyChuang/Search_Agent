# 训练步骤恢复与模型基线

训练任务的进度卡显示「待查题」「题目已保存」「计划草稿已保存」「计划已保存」。Flyway V7 在原任务表中增加题目目录和计划草稿两处检查点及写入时间。旧任务继续读取原有状态和结果，未完成的旧任务从第一个可用检查点开始。Java 和 Python 的内部工具契约一并更新。

| 检查点 | 保存内容 | 重新领取后的动作 |
| --- | --- | --- |
| 查题完成 | 当前岗位方向的公开题干、选项、来源和版本 | Python 复用目录，直接调用生成计划工具 |
| 生成完成 | Java 验证后的岗位分析、步骤和所选题目快照 | Java 直接保存计划结果，省去模型调用 |
| 保存完成 | 最终结果和 `SUCCEEDED` 状态在同一更新中写入 | 相同请求编号与内容返回已有结果 |

Python 检查工具名称、调用数量和参数结构。计划生成收到无效工具响应时，复用已保存的题目目录补试一次。若补试仍失败，任务卡会提示模型返回格式错误，并保留查题进度。Java 按内部服务令牌和当前任务租约授权，校验计划引用属于已保存目录，并拒绝重复题目和不同内容的草稿覆写。阶段记录与任务 ID 对应，模型日志记录任务 ID、步骤、调用耗时及供应商返回的输入和输出 token。

## 真实模型基线

按[本地启动说明](career-agent-day-1-2026-11-06.md)启动服务。准备一个没有已确认经历和练习记录的演示账号，在模型配置中保存支持工具调用的默认对话模型。下列命令从 `api` 目录运行，会为演示账号写入合成岗位和经历，并生成一组训练、复习与面试任务。

```powershell
uv run --locked python -m scripts.check_career_workflow demo_user
```

脚本输出每个任务的 ID、最终状态与端到端耗时。按任务 ID 从 Python 日志找到对应的 `Career model` 行，汇总输入和输出 token。供应商未返回的 usage 记为缺失。重新测量时使用新的演示账号和同一模型，以避免历史练习影响复习输入。

2026-11-09 通过 Vite、Java、隔离 MySQL、Python 和现有 Comet 模型配置，使用 `deepseek-flash` 跑通一组固定合成岗位与经历。三项各运行一次。耗时包含派发、保存和脚本轮询，token 来自供应商返回的 usage。

| 任务 | 状态 | 端到端耗时 | 输入 token | 输出 token |
| --- | --- | ---: | ---: | ---: |
| 训练计划 | 成功 | 11.336 秒 | 1,412 | 609 |
| 复习建议 | 成功 | 8.305 秒 | 1,424 | 884 |
| 模拟面试 | 成功 | 7.170 秒 | 570 | 668 |

训练计划耗时覆盖查题和生成两次模型调用。以上是功能验收和单样例基线，后续对照实验沿用相同模型与输入设置。

## 步骤恢复实测

2026-11-09 在隔离 MySQL 8.4.13 和本地 OpenAI 兼容模型替身上运行两个训练任务。分别阻塞生成模型的响应、阻塞 Python 在草稿落库后的响应。观察两个任务均处于第 1 次执行后终止 Java，重启并等租约自然到期。

| 中断点 | 恢复后的查题模型调用 | 恢复后的生成模型调用 | 持久化结果 |
| --- | ---: | ---: | --- |
| 题目目录已保存，生成尚未完成 | 0 | 1 | 原任务第 2 次执行成功，保存 1 份计划 |
| 计划草稿已保存，任务尚未确认成功 | 0 | 0 | 原任务第 2 次执行成功，保存 1 份计划 |

两条原始请求再次提交均返回原任务。空库 V1–V7、现有求职库 V6–V7、Maven 10 项集成测试、Python Ruff 和 6 项求职测试、前端类型检查和生产构建通过。浏览器主流程使用本地模型及账号资料替身，真实供应商测量见上表。
