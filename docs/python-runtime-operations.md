# Python 运行架构与验收

FastAPI 负责求职 API、对话和 Agent 工具编排。独立 Python Career Worker 负责 MySQL 队列、检查点恢复、面试评估补偿与提醒。PostgreSQL 承载消息、MCP 授权、岗位上下文版本及工具结果归档。Redis 承载单聊事件、确认请求和共享缓存。Celery Worker 与 Beat 处理资料解析、长期记忆和定时研究。`backend/src/main/resources/db/migration` 中的 Flyway SQL 由 Python 迁移器执行，既有版本和校验和继续有效。

## 升级顺序

1. 保留环境变量和数据备份，确认 API 与 Worker 共用同一个 `FERNET_KEY`。
2. 使用根目录 README 的 Compose 命令更新。API 等数据库迁移通过后才接受生产请求，Career Worker 等 API 健康后启动。开发环境可使用 `CAREER_NATIVE_WORKER_ENABLED=true` 在 FastAPI 内启动 Worker。
3. 在 MCP 工具清单同步并授权。外部工具默认进入待确认列表。通过部署侧独立审核的只读工具，可由所属用户在清单中开通限时预授权。对话创建定时研究继续使用待确认列表。审批保留五分钟，仅消费一次。执行结果超时时先核对远程服务状态。
4. 在已有求职对话中打开「上下文约束」。手动修改和回滚形成新版本，后续生成使用当前有效版本。旧对话首次写入版本时从历史读取初始约束。

训练 Harness V2 使用 MySQL 迁移 `V20__career_training_harness.sql`。API 与 Worker 升级前应用迁移。新任务默认执行 V2 契约和定向修复，练习反馈保留 V1 策略，可通过 `CAREER_TRAINING_LEARNING=objective-practice-v2` 试用带时效和置信度的技能状态。`CAREER_TRAINING_REPAIR=regenerate-v1` 使用整份重生成，`CAREER_TRAINING_HARNESS=v1` 回退新任务的整个执行策略。已提交任务依据各自冻结的版本恢复。架构、回放和对照命令见 [备考 Harness V2 技术报告](career-training-harness-v2.md)。

## 清单落地与验证

| 项目 | 本轮实现 |
| --- | --- |
| 工具权限与安全 | 调用前从数据库核验服务归属、启用状态和本地授权。敏感操作需确认。MCP 同源发送，关闭自动重定向，在拨号时校验全部解析地址并只连接已校验 IP。部署环境可进一步限制出站访问。 |
| 共享缓存 | 生产 Compose 默认启用描述缓存和记忆向量缓存，允许独立回退。MCP 配置修改发布版本通知，数据库修订也参与缓存键。Redis 失败时直接拉取，记忆事实仍从图数据库读取。 |
| Worker | 独立进程运行，每 20 秒续租。短暂模型网络异常、限流与任务超时有限退避。接管保留检查点，失租取消执行。关闭时释放当前租约。 |
| Agent 评测 | `career_workflow_eval` 检查最终计划约束、岗位技能覆盖、有效工具提交和检查点恢复。`--live-user <UUID>` 使用该本地账户配置的真实模型执行同一组合成案例。 |
| 上下文与工具归档 | 岗位上下文支持版本化修改与回滚。超过 500 Token 的工具输出可加密归档，单条限制 2 MB，七天内可凭引用分页回读。每用户最多保留 128 条有效记录及 16 MB 密文。回读限每用户每分钟 60 次。Celery Beat 每五分钟清理一批过期数据。 |
| SSE | 普通单聊和求职单聊统一使用 Redis Streams。`Last-Event-ID` 与当前执行轮次匹配时按游标重放，失效时恢复快照或读取数据库历史。多人群聊采用原实时广播机制。 |
| RAG | 初始窗口已满且不同父块不足时，有界扩大一次召回。`career_rag_eval` 在同一标注集对照固定窗口和扩窗的检索 P95、父块填充量与文档命中，使用 `--rerank-user <UUID>` 可增加 Rerank 对照。 |
| 训练反馈 | `career_attempt_replay --user <UUID> --job <UUID>` 仅输出作答聚合统计，按计划创建时间切分既有信号与后续结果。相邻计划窗口可能重叠，结果属于观察性统计。 |
| 监控 | 任务页展示成功备考步骤 P95、失败率和恢复任务成功率。模型成本沿用采样 Trace 的估算，缓存每 50 次记录命中与降级统计。Worker 每分钟报告队列等待和过期租约，队首超过 300 秒或存在已过期租约时记录警告。 |

当前版本的逐项变更、测试证据及部署顺序见 [正确性、安全性与恢复验收记录](runtime-correctness-review.md)。

## 岗位约束与运行配置

- 岗位约束面板从 API 读取可编辑字段。当前覆盖求职目标、复习顺序、截止时间、意向城市、实习时长、异地偏好和简历素材偏好。岗位实际地点从 MySQL 的岗位记录读取。简历可用经历以业务记录的确认状态为准。
- 输入「截止时间改为周五，请按照新的截止时间重新安排我的训练计划」会保存截止时间「周五」，并用当前约束快照提交计划。规则无法可靠拆分时保留原文，模型按当前已保存约束处理本轮问题。编辑、取消和回滚均保留版本控制，约束面板可核对来自历史的待确认字段。
- `MCP_REVIEWED_READS` 默认值为 `[]`。部署侧审核远端实现、允许的响应和参数后，可在此 JSON 数组中填入 `user_id`、`server_id`、`url`、`tool`、`schema_digest`、带时区的 `expires_at` 和 `arguments`。`arguments` 为参数名到精确标量候选值的映射，例如 `{"category":["public"],"page":[1,2]}`。只读预授权适用于无凭证的 HTTPS Streamable HTTP 工具，设置后，所属用户还需在清单中选择「只读预授权」。每用户每工具每分钟最多自动查询 20 次。移除部署策略、关闭用户授权或等待到期均可撤销自动权限。
- 在模型设置页可为对话和多模态模型填写供应商公布的窗口。配置后，单聊和备考 Worker 按实际选中模型的窗口保留输出空间。普通和岗位聊天的环境默认值仍可用。Token 计数和图片费用采用本地估算。明确小于备考最小有效输入的窗口会给出预算错误，适合改用更大窗口的模型。
- `CAREER_ALERT_WEBHOOK_URL` 接收队列异常和恢复的 HTTPS POST，可用 `CAREER_ALERT_WEBHOOK_TOKEN` 作为 Bearer 凭证。PostgreSQL 在同一事务记录待发送事件。首次发送失败会重试，接收端按 `Idempotency-Key` 去重。事件只携带队列总量、过期租约、等待时间和状态。

上线前先应用 PostgreSQL 迁移 `91d41ef3b70c`。用测试账号执行 `python -m eval.career_workflow_eval --live-user <用户UUID>`，记录模型是否在计划步骤中采用截止日期、主题覆盖和工具校验结果。在目标环境通过实际反向代理核对重连续传，在独立压测环境记下吞吐量和恢复时间，并确认 Webhook 接收了触发与恢复两个事件。

本机使用真实 PostgreSQL、Redis 和 MySQL 验证了字段级版本、审批隔离、跨客户端限频和 Worker 恢复。两个 Uvicorn 实例共用本地 Redis，停止初始读取实例后，存活实例从原游标恢复，16 路并发重放均无重复事件。Webhook 失败重试使用测试接收端。模拟模型的截止时间检查为 2/2，检查点恢复为 2/2。本机的实际模型端点不在可达范围，生产负载、反向代理与真实告警接收待目标环境验收。

## 验收命令

```powershell
cd api
uv run --locked ruff check app
uv run --locked python -m unittest discover -s tests
uv run --locked python -m eval.career_workflow_eval
uv run --locked python -m eval.career_worker_load
```

`career_worker_load` 使用本机 MySQL 的隔离测试表。验证重复提交、并发认领上限、租约接管、检查点复用和拒绝旧执行者写回，运行结束自动清理测试表。

## 本机验收记录

- 47 项后端测试及前端生产构建通过。PostgreSQL 迁移已应用到本机实例，并验证了版本冲突、回滚及工具归档的岗位隔离。
- MySQL 测试中，16 次提交对应 8 个唯一任务，12 路并发认领首次只放行 4 个。过期租约接管复用了检查点，旧执行者无法回写。
- 受控模型评测的最终约束和任务质量均为 4/4，恢复为 2/2。有效工具提交为 4/6，包含刻意安排的两次无效提交。真实作答回放找到了 7 份计划，其中没有足够的薄弱技能样本。
- 40 条 RAG 标注查询对照中，两种策略的 Recall@5 均为 90%，父块结果均填满 200 个位置。这批样本未触发扩窗。候选不足时的扩窗路径由单独回归测试覆盖。
- 两条 Redis 客户端连接验证了授权单次消费、事件游标重放和版本失效。真实模型与 Rerank 服务的表现、生产环境的容量和告警接收仍需验收。

生产部署验收包括 `career-worker` 容器日志、缓存命中率、告警接收情况，以及用独立测试账户验证跨实例断线重连、配置撤销和模型任务质量。
