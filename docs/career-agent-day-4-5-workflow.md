# 第四、五天 · 岗位训练与申请材料

按[本地启动说明](career-agent-day-1-2026-11-06.md)启动 React、Java 和 Python 服务。更新时一并重启 Java 和 Python，Flyway 会将求职库升级到 V7。若 Java 使用自定义地址或端口，在 Python 的 `api/.env` 设置 `CAREER_BACKEND_BASE_URL`。Java 与 Python 沿用同一个 `CAREER_AGENT_INTERNAL_TOKEN`。

## 操作顺序

1. 在「岗位与公司」保存目标 JD，在「简历与经历」确认至少一条真实经历。
2. 在「设置 → 模型配置」配置默认对话模型，并启用 `function_call`。模型需要支持通过工具名称指定工具。
3. 打开「岗位训练计划」，选择目标岗位和题库方向。计划卡片显示执行状态、岗位分析、学习步骤和对应题目版本。沿计划链接完成至少一道练习，再点击「根据练习生成复习建议」。失败的任务可在卡片上重试。
4. 在「模拟面试」选择岗位、方向和题目，提交开放回答，查看内置「岗位面试复盘」Skill 的反馈。历史记录保留原始回答、题目和题库评分版本。
5. 在「简历与经历 → 岗位简历版本」查看岗位描述，选择相关的已确认经历，按选择顺序生成并保存草稿。版本预览显示事实依据。浏览器打印视图提供面向外部的草稿正文，可选择「保存为 PDF」。
6. 在「网申助手」为同一岗位关联简历版本、保存表单答案。用户在招聘网站自行完成投递后，在「投递看板」手动更新阶段并填写备注。阶段历史与草稿修改分开记录。

## 任务与业务边界

- Java 从登录令牌确定账号，校验岗位与材料归属后保存任务和输入快照。相同账号重发同一请求编号和内容会返回已有任务，编号复用于不同内容返回 409。
- Java 有两个派发工作槽。每次领取写入执行代次和两分钟租约，服务中断后可重新领取过期任务。Python 从 Comet 读取当前账号的模型配置。训练工具限于查题与生成计划，Java 校验题目版本、岗位方向和租约，分别保存题目目录和计划草稿。最终计划与任务成功在一次更新中完成。重试会从最后一个已保存的步骤继续。见[训练步骤恢复与模型基线](career-agent-training-checkpoints.md)。
- 简历版本保留生成时的事实快照。每个账号的每个岗位有一份网申草稿，关联的简历必须属于同一账号和岗位。草稿和阶段更新用修订号防止覆盖其他窗口的变更。
- 当前交付范围为单轮模拟面试、用户挑选事实生成的岗位简历草稿，以及人工网申和投递维护。
