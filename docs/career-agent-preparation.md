# 个人资料与求职 Agent 执行记录

从「我的资料」打开知识库，在文件旁点击「用于备考」可进入训练计划。训练计划、AI 模拟题和模拟面试也可直接选择最多三份资料。服务端按登录账号读取原文并提取与岗位相关的段落。已上传且可提取文本的资料可以使用，向量模型额度只影响知识库的向量索引。

执行结果的「本次备考资料」提供原文回查，「执行记录」显示执行代次、步骤、耗时及模型提供的 token 数。选中的资料是备考参考。简历事实仍来自用户确认的经历。联网面经使用公司和岗位名称作为检索条件。

## 实现

| 能力 | 实现 |
| --- | --- |
| 上下文预算 | 用 cl100k 计数装配任务输入，限制为 9,000 tokens。题目目录另有 4,000 tokens 上限，保留题号与版本。优先保留岗位、作答、评分要求与偏好，再装配经历和旧反馈。统计中的模型 token 使用量取自服务商。 |
| 原文与恢复 | Java 保存裁剪后的任务上下文、资料引用、内容版本和技能版本。Python 每次执行重新校验原文归属与版本，再装配摘录。训练继续复用题目目录和计划草稿检查点。 |
| 跨任务记忆 | 用户在岗位训练页维护该岗位的备考偏好，支持修改和清空。Java 校验修改版本。用户经历、备考偏好和执行快照各自维护。 |
| Skill 与工具治理 | 可以选用技能中心已启用的 Skill。Python 按任务读取选中版本并提供方法指引，工具仍由任务类型确定。Java 校验用户归属、共享服务令牌、租约、执行代次和候选题版本。 |
| 调度与过载 | 同用户同岗位依队列顺序执行，不同岗位可并行。MySQL 原子认领，全局最多 4 个执行租约，同用户最多 2 个。最多排队 200 个任务，同用户最多 20 个。当前每个 Java 进程有两个派发线程。 |
| 追踪 | 执行事件按任务、代次和序号去重。用户可以查看自己的事件，任务回写会拒绝过期代次。 |

设计借鉴了按需装配上下文、工作状态与持久记忆分层，以及调用前后检查。实现复用现有 Comet 原文存储和技能目录，并使用 Java/MySQL 管理任务状态。 [Deep Agents 上下文工程](https://docs.langchain.com/oss/python/deepagents/context-engineering) · [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) · [Claude Code Hooks](https://code.claude.com/docs/en/hooks) · [Claude Code Skills](https://code.claude.com/docs/en/skills)

部署时更新 Python、Java 和前端，Java 启动后应用 Flyway V9。当前范围为求职任务。每家供应商独立配额、技能包安装、子 Agent、外部网申回执和跨聊天语义压缩仍属于后续工程。

## 验收

- 隔离 MySQL 验证 V1 至 V9 迁移、同岗位顺序、跨岗位并发、来源和执行记录隔离、重复事件及旧代次回写。
- 浏览器使用合成资料与模型响应验证资料选择、Skill 选择、原文预览、执行记录和既有求职流程。
- 真实 DeepSeek 使用合成文本验证模拟出题、训练计划、作答复盘及复习建议。记录模型返回的用量，无性能收益测量。
